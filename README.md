## 💡 ディレクトリートラバーサルとは？

**ディレクトリートラバーサル**（パストラバーサル）は、Webアプリケーションが意図しないディレクトリーやファイルにアクセスできてしまう脆弱性です。

### 基本的な仕組み
- 通常、ユーザーは `/app/files/` 内のファイルのみアクセス可能
- `../` を使って上位ディレクトリーに移動することで、制限を回避
- 例: `../../etc/passwd` で システムファイルに到達

### よくある攻撃例
```
入力: ../../etc/passwd
結果: /app/files/../../etc/passwd → /etc/passwd (正規化後)
```

### 対策の基本
- **入力検証**: 危険な文字列（`../`）のチェック
- **パス正規化**: 相対パスを絶対パスに変換
- **アクセス制御**: ベースディレクトリー外へのアクセス禁止

> 📖 **詳細な技術解説**: [脅威モデルと技術解説](docs/threat-model.md) / [技術詳細ドキュメント](docs/technical-details.md)

## ✨ 特徴
- **欠陥フィルターごとの学習設計**: フィルターを5種（なし／生の `..` を弾く／`../` を消す／デコードして弾く／拡張子チェック）用意し、それぞれを破る手法が1つずつ対応する
- **実際の回避手法**: URLエンコード・入れ子・二重エンコード・ヌルバイトを、効くフィルターと対で学べる
- **安全な対策確認**: Safe Mode でベースディレクトリーチェックによる防御を体験
- **対策の比較**: 同じ入力を3つの対策（ブラックリスト／正規化後チェック／許可リスト）に通し、どれがどこで止めるかを並べて表示（弱いブラックリストは漏れることが見える）
- **途中経過の表示**: 入力→フィルター通過後→URLデコード後→正規化後→取得パスを順に見せる
- **ゲーミフィケーション**: フラグファイル発見でバッジ表示
- **日英対応**: 画面を日本語／英語で切り替え（`?lang=ja`・`?lang=en` でも指定できる）
- **教育的UI**: タブ形式（攻撃体験・座学）とアコーディオン形式の解説

## ⚙️ 仕様

### UI
- **ファイルツリー表示** `/app/files/` 以下をナビゲーション表示
- **パス入力フォーム** + 「Fetch」ボタン
- **出力ビュー** ファイル内容／エラーメッセージを表示
- **フィルター切替** なし／生の `..` を弾く／`../` を消す／デコードして弾く／拡張子チェック（画像だけ）
- **ヒント機能** いま選んでいるフィルターの欠陥と、効く手法を表示
- **モード切替** Vulnerable Mode（脆弱挙動） / Safe Mode（対策実装）
- **対策の比較** 同じ入力を3つの対策に通した結果を表で表示
- **言語切替** 日本語／英語（画面右上のボタン）

### 仮想ファイルシステム例

```
/app/files/
  readme.md -> "This is a public readme..."
  public.txt -> "公開ファイルです..."
/secrets/
  flag.txt -> "FLAG{day068_success}"
/etc/
  passwd -> "root:x:0:0:root:/root:/bin/bash\nuser:x:1000:1000:user:/home/user:/bin/bash"
```

### フィルターの設計

フィルターごとに欠陥が1つあり、それを破る手法が1つ対応します。目標はいつも `/secrets/flag.txt` を取ることです。

| フィルター | 欠陥 | 破る手法 | 例 |
|---|---|---|---|
| なし | フィルターなし | そのまま | `../../secrets/flag.txt` |
| 生の `..` を弾く | デコード前の入力しか見ない | URLエンコード | `%2e%2e/%2e%2e/secrets/flag.txt` |
| `../` を消す | 消したあと見直さない | 入れ子 | `....//....//secrets/flag.txt` |
| デコードして `..` を弾く | 1回だけデコードし、後段でもう1回デコードされる | 二重エンコード | `%252e%252e%252f%252e%252e%252fsecrets%252fflag.txt` |
| 拡張子チェック（画像だけ） | 末尾の拡張子だけ見て、取得は `\0` で切る | ヌルバイト | `../../secrets/flag.txt%00.png` |

### パス解決の挙動について

本ツールでは、**実際のWebサーバーに近い挙動**を再現しています。

1. **フィルター**: フィルターが入力を拒否するか、入力を変える（`../` を消す等）
2. **URLデコード処理**: 入力をURLデコードします
3. **パス結合**: `/app/files/` をベースディレクトリーとして結合
4. **正規化**: スタック方式で `..` を解決
5. **ヌルバイトで切る**: `\0` 以降を切り捨てる（古い言語の `open()` の再現）
6. **仮想ファイルシステム**: VFSで定義されたファイルへアクセス

**パス例**:
- `%2e%2e/%2e%2e/secrets/flag.txt` → URLデコード → `../../secrets/flag.txt` → 正規化 → `/secrets/flag.txt`
- `../../etc/passwd` → 結合 `/app/files/../../etc/passwd` → 正規化 → `/etc/passwd`

**モード別の動作**:
- **Vulnerable Mode**: ベースディレクトリーチェックなし（脆弱性を体験）
- **Safe Mode**: 正規化後にベースディレクトリー外へのアクセスをブロック（対策を確認）

## 📋 使い方
1. [デモページ](https://ipusiron.github.io/path-escape/) を開く
2. **攻撃体験タブ**で基本的なファイルアクセスを確認
   - 例: `/app/files/readme.md`
3. **robots.txtを探索**: `/robots.txt` で機密パスのヒントを発見
4. **ディレクトリートラバーサル攻撃**: `../../etc/passwd` や `../../secrets/flag.txt` を試す
5. **各フィルターに挑戦**（ヒントボタンで、効く手法がわかります）:
   - **なし**: そのまま `../../secrets/flag.txt`
   - **生の `..` を弾く**: URLエンコード `%2e%2e/%2e%2e/secrets/flag.txt`
   - **`../` を消す**: 入れ子 `....//....//secrets/flag.txt`
   - **デコードして `..` を弾く**: 二重エンコード `%252e%252e%252f%252e%252e%252fsecrets%252fflag.txt`
   - **拡張子チェック（画像だけ）**: ヌルバイト `../../secrets/flag.txt%00.png`
6. **Safe Mode**: ベースディレクトリー外アクセスをブロックする防御機能を確認
7. **座学タブ**: アコーディオン形式で技術的な解説と対策を学習

## 🎯 利用シナリオ

このツールならではの使い方

- 正しい対策は正規化してから基準の下か確かめることを確かめる（対策設計の授業）：`../../secrets/flag.txt`は、対策なし（none）の脆弱モードでは`/secrets/flag.txt`に届きフラグを読めてしまう。同じ入力を安全モードにすると、パスを正規化したうえで基準のフォルダー`/app/files/`の下にあるかを確かめ、外へ出る結果は拒否される。禁止語の一覧ではなく、正規化してから基準の下かを見るのが正しい対策だと、同じ入力で確かめられる
- 素朴な文字の除去はすり抜けられることを確かめる（対策の落とし穴の授業）：`../`を取り除くだけの対策（strip）に`....//....//secrets/flag.txt`を入れると、`../`を消したあとに残った文字が`../`に戻り、フラグに届いてしまう。危ない並びを文字列として消すだけの対策が、重ねた書き方で破られることを確かめられる
- ヌルバイトで拡張子の確認をすり抜けられることを確かめる（入力の切り詰めの授業）：画像の拡張子を求める対策（ext）に`../../secrets/flag.txt%00.png`を入れると、ヌルバイト（%00）より後ろが切り捨てられ、残った`flag.txt`がフラグに届く。末尾だけを見る確認が、途中の区切り文字で破られることを確かめられる

### シナリオ1: セキュリティ研修での活用
**対象**: 新入社員や開発チーム向けのセキュリティ研修

企業のセキュリティ研修において、実際のサーバーを使わずに安全にディレクトリートラバーサル攻撃を体験できます。

1. **導入（10分）**: 座学タブのアコーディオンセクションで基本概念を学習
2. **実習（20分）**:
   - 「なし」で基本的なトラバーサルを体験
   - 「生の `..` を弾く」でURLエンコード回避を学習
   - 「`../` を消す」「デコードして弾く」「拡張子チェック」で、フィルターごとに効く手法が違うことを確認
3. **防御策の確認（10分）**: Safeモードに切り替えて、ベースディレクトリーチェックによる対策を確認
4. **コードレビュー（10分）**: DevToolsを使って実際のパス正規化処理を確認

研修後は、参加者が自社のコードレビューで同様の脆弱性を発見・修正できるようになります。

### シナリオ2: CTF・セキュリティコンテストの準備
**対象**: CTF参加者やペネトレーションテスター志望者

CTFでよく出題されるディレクトリートラバーサル問題の練習ツールとして活用できます。

1. **基礎トレーニング**:
   - さまざまなエンコーディング手法（部分・完全URLエンコード）の理解
   - OSごとのパス表記の違い（Linux: `/etc/passwd`、Windows: `C:\windows\system32`）の学習
2. **応用テクニック**:
   - ヌルバイト（`%00`）による拡張子チェック回避
   - 入れ子（`....//`）による「`../` を消す」フィルターの回避
   - 二重エンコード（`%252e`）による「デコードして弾く」フィルターの回避
3. **実戦的な練習**:
   - robots.txtからの情報収集
   - 段階的なフィルター回避テクニックの習得
   - エラーメッセージの違いによる挙動の理解

実際のCTFやバグバウンティプログラムで遭遇する問題に対応できる実践的なスキルが身につきます。

## 🔍 どうやって攻撃者は機密パスを見つけるのか？

攻撃者が`/secrets/flag.txt`のような、隠されたファイルパスを知るには、さまざまな手法があります。

代表例として、公開リポジトリに残されたソースや設定ファイル、`robots.txt`/`sitemap.xml`、誤って有効にしたディレクトリー一覧、古いバックアップ、あるいは辞書的なファイル名の列挙（ワードリスト）などが挙げられます。

PathEscapeでは学習のために「予測可能なファイル名」「ソースの漏洩」「レスポンスの違いによる列挙」を教材化し、どのように発見され得るかを体験できます。

**実運用では** 機密ファイルを公開ドキュメントルートに置かない、詳細なエラーメッセージを出さない、リポジトリにシークレットを含めない等の対策が必須です。
