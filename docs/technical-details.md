## パスの正規化

`normalizePath(path)` はスタック方式です。`\` を `/` にそろえ、`/` で分割し、`.` は無視、`..` は1つ戻し（絶対パスでは根より上に行かない）、それ以外は積みます。

```javascript
normalizePath('/app/files/../../etc/passwd'); // → '/etc/passwd'
normalizePath('/app/files/..\\..\\etc/passwd'); // → '/etc/passwd'
normalizePath('../../etc'); // → 'etc'（相対の先頭の .. は残す）
```

`urlDecodeOnce(s)` は `decodeURIComponent` を1回だけ呼び、壊れた並び（`%ZZ` など）はそのまま返します。`truncateAtNull(s)` は最初の `\0` 以降を切り捨てます（C や古い PHP の `open()` が `\0` でパスを切ることの再現）。

## 仮想ファイルシステム（VFS）

`js/vfs-data.js` が `window.VFS` を直接セットします（JSON を `fetch` しないので `file://` でも動きます）。キーは絶対パス、値はファイルの中身です。

```javascript
window.VFS = {
  '/app/files/readme.md': '...',
  '/app/files/public.txt': '...',
  '/robots.txt': '...',
  '/secrets/flag.txt': 'FLAG{day068_success}',
  '/etc/passwd': '...',
};
```

ファイルツリーには `/app/files/` 以下だけを出します。目標は、外にある `/secrets/flag.txt` を取ることです。

## 取得の流れ

`resolve(userInput, stage, mode, vfs)` が1回で評価します。

1. フィルター（`stage`）が入力を**拒否**するか判定する（`blocks`）
2. フィルターが入力を**変える**（`sanitize`。`../` を消す、デコードして渡す等）
3. URLデコードを1回する
4. 先頭が `/` でなければ `/app/files/` を前置し、重複スラッシュを畳む
5. 正規化する（`..` を解決）
6. `\0` 以降を切る
7. `mode==='safe'` なら、`/app/files/` の外なら拒否する
8. VFS を引く

返り値は `{blocked}` / `{ok, path, content, flag}` / `{ok:false, error}`。`steps` に各段の途中経過（入力→フィルター通過後→デコード後→正規化後→取得パス）が入り、画面で「どこで止まったか」を見せます。

## フィルターの模型

教材の要点は、**回避手法は特定の欠陥フィルターを破るもので、手法ごとに狙う相手が違う**ことです。フィルターを5種用意し、各フィルターを破る手法が1つ対応します（`STAGE_INFO`）。

| ステージ（id） | 欠陥 | 破る手法 | 仕組み |
|---|---|---|---|
| `none` | フィルターなし | そのまま | `../../secrets/flag.txt` |
| `raw` | デコード前の入力に `..` があれば拒否 | URLエンコード `%2e%2e` | 生入力に `..` が出ない |
| `strip` | `../`・`..\` を消して、結果を見直さない | 入れ子 `....//` | 消すと `../../` が組み上がる |
| `decode` | 1回デコードして `..` を弾き、デコード済みを後段へ渡す | 二重エンコード `%252e` | 後段がもう1回デコードする |
| `ext` | 末尾の拡張子（画像）だけ見て許可 | ヌルバイト `%00` | 取得は `\0` で切るので、`flag.txt%00.png` は拡張子 `.png` で通り取得は `flag.txt` |

ポイントは、効かない手法を「動作する」と案内しないことです。たとえば `..././` はこのツールのスタック正規化では `...`（3点）という普通の名前になり遡上しません。`....//` は「`../` を文字列で消すフィルター」を破る手法で、`strip` ステージでだけ効きます。ステージ×手法の全組み合わせは `test/core.test.js` の真理値表で固定しています。

## モードと安全な取得

モードはフィルターと直交します。

- **Vulnerable**: 正規化後の base チェックをしない（脆弱性を体験）
- **Safe**: 正規化後に `/app/files/` の外へ出る入力を拒否する（対策を確認）

Safe モードは、どのフィルターでも、フラグに届く入力をすべて止めます。実際の対策は、正規化してから base の内側かを確かめる、許可リストで絞る、`realpath` で実体を確かめる、などです。
