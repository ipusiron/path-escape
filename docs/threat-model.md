# PathEscape — Threat Model & Technical Notes

本ドキュメントでは、PathEscapeにおけるディレクトリートラバーサル脆弱性の仕組みと対策を解説します。  

---

## 1. 脆弱性の概要

ディレクトリートラバーサル（Directory Traversal）とは、ファイルパスの入力処理が不適切な場合に、  
`../` を利用して本来アクセスできない上位ディレクトリーや機密ファイルを参照できてしまう脆弱性です。  

典型的な例：

```
GET /view?file=../../etc/passwd
```

→ サーバー側が正規化やアクセス制御を行っていないと、`/etc/passwd` がそのまま返される。

---

## 2. 攻撃シナリオ

1. ユーザー入力をそのままファイルパスに結合してしまう
2. 攻撃者は `../` を含むパスを入力する
3. サーバーは正規化を行わず、OSにファイルパスを渡す
4. OSは `..` を解決し、親ディレクトリーを参照
5. 本来閲覧不可の機密ファイル（例：`/etc/passwd`）が取得される

---

## 3. PathEscape における再現

PathEscape では以下を再現しています：

- **Vulnerable モード**  
  - 入力値を結合後、正規化してもベースディレクトリーチェックを行わない  
  - 結果として `../../etc/passwd` などで機密ファイルを取得可能

- **Safe モード**  
  - 正規化後に必ず `startsWith(BASE)` チェックを実施  
  - ベース外のパスは「Access denied」でブロック

---

## 4. 教材としてのポイント

- **なぜ `../etc/passwd` ではなく `../../etc/passwd` が必要なのか** → ファイルシステムの階層構造を理解するきっかけになる  
- **ブラックリストの落とし穴** → 欠陥フィルターごとに、それを破る手法が違うことを体験  
- **ホワイトリスト・正規化の重要性** → Safeモードの実装で体感  

---

## 5. 実運用での対策

- **正規化**：入力パスを OS に渡す前に必ず正規化し、`..` を解決する  
- **ホワイトリスト**：アクセス可能なディレクトリー・ファイルをホワイトリストで管理  
- **chroot/jail 的隔離**：Webアプリが参照できるファイル空間を隔離する  
- **ライブラリ利用**：フレームワークのセキュアなファイルアクセス関数を使用する  
- **監査ログ**：不正なパス入力を記録し、攻撃兆候を早期検知

---

## 7. 注意事項

- PathEscape は教育目的でのみ使用してください  
- 実運用環境で同様の脆弱性を残すことは重大なセキュリティリスクです  
- デモで体験する内容を実システムで再現しないようご注意ください
